# Фронтенд и браузер

Фронтенд – часть сайта, которая работает в браузере у посетителя: страницы, скрипты, формы. Всё, что попало во фронтенд, может прочитать любой человек, открывший сайт. Поэтому главное правило здесь: в браузер уходит только то, что не жалко показать всем.

Как читать таблицу: «как проверить» – команда или действие, после которого понятно, всё ли в порядке. Вместо `https://сайт` подставьте адрес своего сайта, вместо `https://api…` – адрес своего API (API – адрес, по которому программы обмениваются данными с вашим сервером). Команды написаны по документации; сначала попробуйте их на одном проекте.

| № | Что | Зачем | Как проверить | Как часто |
|---|-----|-------|---------------|-----------|
| F1 | Заголовок CSP (Content Security Policy – список источников, откуда странице можно загружать скрипты) включён в режиме блокировки, а не только «отчёт» | Чужой скрипт, внедрённый на страницу, не запустится | `curl -sI https://сайт \| grep -i content-security` – должна быть строка `content-security-policy`, а не `...-report-only` | При каждом релизе |
| F2 | Заголовки HSTS (браузер ходит на сайт только по HTTPS), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` | Браузер не открывает сайт без шифрования и не отдаёт лишнего другим сайтам | `curl -sI https://сайт`; сервис securityheaders.com | Раз в месяц |
| F3 | В собранном коде сайта нет секретов (ключей API, приватных ключей) | Всё, что уехало в браузер, читает любой | `grep -rlE "sk-ant-\|sk-proj-\|sk-or-\|sb_secret_\|service_role\|BEGIN (RSA\|OPENSSH\|EC) PRIVATE" .next/static dist build out` – ждём пустой вывод | При каждом релизе |
| F4 | В Next.js переменные с префиксом `NEXT_PUBLIC_` содержат только публичные значения | Этот префикс вшивает значение прямо в код, который получает браузер | `grep -rn "NEXT_PUBLIC_" --include="*.ts" --include="*.tsx" --include="*.js" . \| grep -iE "secret\|private\|service\|token"` – ждём пустой вывод | При каждом релизе |
| F5 | В браузере только публичный ключ Supabase (`sb_publishable_` или старый `anon`) | Секретный ключ (`sb_secret_` или `service_role`) обходит все правила доступа к базе | поиск из F3 плюс вкладка Network (сетевые запросы) в инструментах разработчика браузера | При каждом релизе |
| F6 | Данные Telegram Mini App (`initData` – строка, которую Telegram передаёт приложению) проверяются на сервере по подписи HMAC и по свежести `auth_date` | Иначе любой подставит чужой Telegram ID и войдёт под другим человеком | найти в коде сервера проверку с ключом из строки `WebAppData`; запрос с поддельным `initData` должен вернуть ошибку 401 | При каждом релизе |
| F7 | Сторонних скриптов минимум; каждый загружается со своего домена или с SRI (контрольной суммой файла, которую проверяет браузер) | Если взломают чужой CDN (сервер, раздающий файлы), это не станет взломом вашего сайта | `grep -rnE "<script[^>]+src=[\"']https?://" .` и сверка со списком в CSP | Раз в квартал |
| F8 | Версии библиотек зафиксированы lock-файлом (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`), установка на сервере через `npm ci` | Не подтянется свежая заражённая версия пакета | lock-файл лежит в репозитории; в скриптах деплоя (выкладки на сервер) `npm ci`, а не `npm install` | При каждом релизе |
| F9 | `npm audit` не находит критичных уязвимостей | Известные дыры в библиотеках закрыты | `npm audit --omit=dev` | Раз в неделю |
| F10 | Кука сессии (запись в браузере, по которой сайт узнаёт пользователя) стоит с флагами `Secure; HttpOnly; SameSite` | Скрипт на странице не прочитает сессию, чужой сайт не отправит запрос от имени пользователя | `curl -sI https://сайт/страница-входа`, строка `set-cookie` | При каждом релизе |
| F11 | CORS (правило, каким чужим сайтам браузер разрешает читать ответы вашего API) – точный список ваших доменов, не `*` | Чужой сайт не прочитает ответы API от имени вашего пользователя | `curl -sI -H "Origin: https://evil.example" https://api…/ \| grep -i access-control` – в ответе не должно быть `https://evil.example` | При каждом релизе |
| F12 | Наружу не отдаются `.env`, папка `.git`, source maps (карты исходного кода), архивы с резервными копиями | Это готовый набор для взлома | `for p in .env .git/config backup.zip .DS_Store; do echo "$p $(curl -s -o /dev/null -w '%{http_code}' https://сайт/$p)"; done` – ждём 404 или 403 | Раз в месяц |
| F13 | Данные карты вводятся только в виджете платёжной системы (CloudPayments, ЮKassa, Stripe) | Номера карт не проходят через ваш код и сервер | просмотреть код страницы оплаты: поле номера карты принадлежит виджету | Раз в квартал |
| F14 | В `localStorage`, `sessionStorage` и IndexedDB (хранилища в браузере, доступные любому скрипту страницы) нет токенов, ключей, паролей и личных данных | Любой скрипт на странице читает эти хранилища целиком и может унести токен входа | открыть сайт до и после входа, вкладка Application в инструментах разработчика; `grep -rn "localStorage\|sessionStorage" src/` | При каждом релизе |

Подробная пошаговая проверка CSP, HSTS и браузерных хранилищ с правками – в промпте [prompts/csp-hsts.md](../prompts/csp-hsts.md).

## Оговорки

- Поведение префикса `NEXT_PUBLIC_` описано по общему знанию Next.js, а не по конкретной странице документации; страница о безопасности данных – в источниках.
- Один `curl` проверяет одну страницу. Заголовки могут отличаться на разных страницах и поддоменах: проверьте главную, вход, личный кабинет и оплату.
